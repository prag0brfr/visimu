# Third-party notices

visimu was written by Paulo R. A. Gilz and is not released under any
licence. This file is about the *other* people's code it depends on, which is a
separate question with separate obligations.

Nothing here is legal advice. Licences change between releases, so check these
against the versions you actually ship rather than trusting this file.

---

## When the obligations apply

**Running from source, or building for yourself: nothing is required.** Using a
library does not oblige you to do anything. The obligations below are triggered
by *distribution* — handing the built application to someone else.

**Distributing the frozen executable is different.** PyInstaller does not link
against these libraries so much as pack them inside the file it produces, so
sending someone `visimu.exe` sends them a copy of Qt, NumPy and pyqtgraph as
well. Their licences travel with them.

The one that matters is Qt.

C++17 standard library plus the platform's own threading and memory-mapping
calls, which is why `libaoecore.so` / `aoecore.dll` can be shipped without any
of this applying to it.

## Qt / PySide6 — the one to read

PySide6 is offered under the LGPL v3, the GPL, or a commercial licence. Unless
your organisation holds a commercial Qt licence, the copy of Qt inside the
executable you distribute is **LGPL v3**, and LGPL v3 asks three things of you:

1. **Say so.** Tell recipients the application uses Qt, that Qt is licensed
   under the LGPL v3, and where to obtain its source.
2. **Supply the licence text.** Ship a copy of the LGPL v3 (and the GPL v3,
   which it incorporates by reference) alongside the application.
3. **Allow Qt to be replaced.** A recipient must be able to swap in their own
   build of the Qt libraries and have the application use it. This is the
   clause that constrains *how* you package, not just what you write in a file.

On point 3, the two build modes are not equivalent:

- **The folder build** (`python packaging/build_exe.py`, the default) puts the
  Qt DLLs in `dist/visimu/` as ordinary files. A recipient can replace them
  in place. This is the straightforward option, and it is the default for
  reasons of startup time as well.
- **The single-file build** (`--onefile`) packs everything into one executable
  that unpacks itself to a temporary directory at run time. Whether that
  satisfies the relinking requirement is genuinely contested, and it is not a
  question this file can settle for you.

If you distribute this application outside your own machine, prefer the folder
build, include the LGPL text, and say in your release notes that Qt is used
under the LGPL v3.

Qt's own licensing pages: <https://doc.qt.io/qtforpython-6/commercial/index.html>
and <https://www.qt.io/licensing>.

## PyInstaller — no obligation on the bundle

PyInstaller is GPL-licensed, which sounds alarming and is not. It carries an
explicit exception for the applications it builds. From its licence page:

> "The executable bundles generated by PyInstaller from your source code can be
> shipped with whatever license you want, as long as it complies with the
> licenses of your dependencies."

So freezing this application does **not** make it GPL, and you need not include
PyInstaller's licence or credit it in what you ship. The GPL binds only
modifications to PyInstaller itself.

That proviso — "as long as it complies with the licenses of your dependencies"
— is the Qt paragraph above.

<https://pyinstaller.org/en/stable/license.html>

## pyqtgraph and NumPy — attribution only

Both are permissive. Distributing them requires reproducing their copyright
notice and licence text with the distribution, and nothing more: no source
disclosure, no constraint on what you charge, no obligation on your own code.
Copies of both licences live in the installed packages
(`pyqtgraph/LICENSE.txt`, `numpy-*.dist-info/LICENSE.txt`) and can be copied
into a release alongside the executable.

## A practical checklist for a release

If you are handing the folder build to someone:

- [ ] Include `LICENSES/` containing: the LGPL v3 text, the GPL v3 text, the
      pyqtgraph MIT licence, and the NumPy BSD licence.
- [ ] Add a line to the release notes: "This application uses Qt under the
      GNU LGPL v3. Qt source is available from https://download.qt.io/."
- [ ] Ship the folder build rather than `--onefile`, so the Qt libraries remain
      replaceable.
- [ ] Say who wrote the application and under what terms. It currently names
      its author and grants no licence, which permits the recipient nothing. If
      you mean them to be allowed to use it, that needs saying explicitly.

and the PyPI and project pages listed above.
